# Order & Profit — продажи и обратная связь

## Проверенный результат этой ветки

В существующий кабинет добавлен `/sales`: проверенные контакты компаний, переписка с датами и источником, задачи, остановка контактов, очередь предложений, отдельное утверждение точного получателя и текста, журнал событий. Карточка генератора может передать утверждённый черновик в продажи. Локальные/временные ссылки и синтетические карточки в этом переходе блокируются.

Стандартный запуск не подключается к Gmail и не отправляет письма. Подключение Gmail в ChatGPT не предоставляет OAuth-токены этому Python-приложению. Реальная авторизация Google и постоянный хост пока НЕ подтверждены. Эта ветка не означает, что завод уже работает круглосуточно.

## Постоянное подключение Gmail

1. В имеющемся Google Cloud проекте включить Gmail API; настроить OAuth Desktop client и согласие пользователя. Не активировать billing или платные услуги ради этого шага. Если Google требует дополнительные условия/проверку, остановиться на них.
2. Сохранить Desktop client JSON вне репозитория. Для Gmail нужны `gmail.readonly` и `gmail.send`. OAuth приложения в режиме Testing могут требовать повторного входа; срок токена и требования верификации проверить перед постоянным запуском.
3. На компьютере, где будет работать исполнитель, выполнить:

```sh
python -m office.connect_gmail --client /private/google-client.json --output /private/order-profit-gmail.json
```

Откроется Google: выбрать `orderprofit.he@gmail.com` и дать согласие. PKCE/state и loopback callback включены. Не отправлять OAuth-файлы или пароли в чат. Файл с refresh token хранить на приватном диске; права Windows дополнительно ограничить учётной записью исполнителя.

4. Для первого чтения установить `FACTORY_GMAIL_CREDENTIALS` в путь к полученному файлу и запустить существующий `office.py`. Открыть `/sales`, добавить только проверенные стоматологические контакты и нажать «Проверить почту». Письма иных кампаний автоматически в список компаний не добавляются.
5. `FACTORY_MAIL_WORKER_ENABLED=yes` включает проверку переписки известных компаний раз в 5 минут пока запущен процесс. `FACTORY_MAIL_SEND_ENABLED=yes` отдельно разрешает исполнителю отправлять утверждённые письма. По умолчанию обе настройки выключены. Утверждение демо не является утверждением текста письма.

## Пилот до включения отправки

Согласовать первый список компаний и тексты. Сначала проверить реальную авторизацию и получение собственной тестовой переписки, затем одну согласованную отправку. Не отправлять существующим клиентам закрытые или неактуальные ссылки. Глобальное разрешение на пилот в этой ветке не выдано.

Лимит — 5 попыток отправки за последние 24 часа, включая неизвестные результаты. В интерфейсе «Отправлено» означает, что Gmail вернул message id; это не доказательство доставки или прочтения. Повторяющийся текст тому же контакту блокируется. Любой новый ответ или возврат отменяет неотправленные черновики и утверждения этой компании и приостанавливает контакт до ручной проверки. Отказы необходимо оставить заблокированными.

Если процесс прерван при отправке или сеть не вернула результат, статус `UNKNOWN`: повтор не выполняется. Сверить Gmail вручную. Автоматического снятия этой блокировки нет. Отчёт о синхронизации не обновляется до успешного чтения всех известных контактов.

## Постоянный хост и личные данные

Сервер продолжает слушать только `127.0.0.1`. Для доступа с телефона нужен отдельно настроенный приватный runtime/TLS/идентификация владельца. Текущая среда ChatGPT и локальная ссылка не являются постоянным хостингом. Существующий облачный вариант Cloudflare остаётся на прежнем этапе: Access/R2 не подтверждены. Не заменять защиту публичной ссылкой.

CRM, письма, токены, снимки и настоящие email не коммитятся. Рабочие данные находятся вне репозитория; настроить резервную копию постоянного тома перед запуском. Для импорта подтверждённой переписки из коннектора можно вызывать `Sales.import_messages` на приватном исполнителе; импорт не означает живую синхронизацию.

## Проверки

`python -m unittest discover -s tests -q` проверяет существующий генератор и новый почтовый цикл с подставным транспортом. HTTP-проверка проходит цепочку: контакт → черновик → запрет без утверждения → утверждение → одна отправка → запрет повтора → входящий ответ → остановка контакта. Реальные письма тестами не отправляются. Нативный Windows и реальный Gmail transport требуют отдельной проверки после OAuth.

Документация: https://developers.google.com/workspace/gmail/api/guides/sending ; https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list ; https://developers.google.com/identity/protocols/oauth2/native-app .
