# Первый рабочий цикл Order & Profit

Это выполняемый локальный кабинет в том же DENT-ELIT: карточка → версия
проверенных данных → очередь DIRECTOR → существующий генератор → проверки →
просмотр владельцем → утверждение конкретной сборки → черновик письма.
Режим DRY_RUN. Нет отправки, финансовых действий или публикации.

## Открыть на Windows

Скачайте ветку `factory/first-working-cycle` этого репозитория. Нужен Python 3.12
с Python Launcher. Дважды нажмите `run-office.cmd`: он создаст локальное окружение,
установит закреплённые зависимости и запросит пароль кабинета (минимум 16 символов).
Браузер откроется на `http://127.0.0.1:8877/`. Логин: `owner`; пароль — тот, который
вы только что задали. Секрет не записывается в репозиторий.

Другой запуск: `python office.py --open-browser`. Каталог базы по умолчанию:
`~/Order-Profit-Local`, вне публичного исходного кода; `--data` задаёт другое
частное место. `--port` меняет только локальный порт. Публичное прослушивание не
поддерживается. Переменная `ORDER_PROFIT_OWNER_PASSWORD` позволяет задать пароль
из собственного окружения, не через командную строку.

## Где что находится

Слева — карточки клиник; справа — текущая карточка и этапы. «Данные и источники»
показывают статусы фактов и происхождение. Раздел редактирования принимает строгую
конфигурацию предыдущего генератора; новое имя в CRM само по себе не становится
проверенным утверждением. «Демо и тесты» содержит результат сборки, три языковых
версии, широкий/мобильный размер iframe и список неподтверждённых полей.
«Письмо» доступно после утверждения; «История» — события и замечания.

Для безопасного прогона: «Тестовая карточка» → «Проверить данные» → «Собрать демо»
→ дождаться проверок → открыть демо → «Я просмотрел демо» → ознакомиться со всеми
неподтверждёнными полями → «Утвердить эту версию» → «Письмо» → «Создать черновик».
Тестовая карточка синтетическая, изображение — собственная геометрическая
иллюстрация, адресат `test@example.invalid`. Решение тестового исполнителя —
симуляция, не выдаётся за настоящее разрешение владельца на клиентскую отправку.

## Работающий процесс и сохранность

`office/store.py`: SQLite WAL, карточки, неизменяемые версии конфигураций, задания,
согласования и журнал событий. `office/workflow.py`: один DIRECTOR, транзакционный
захват очереди, изолированная сборка через `factory.py`, результаты и проверки.
`office/server.py`: вход владельца, CSRF, API и защищённые файлы демо. База, исходные
материалы и результаты сборок находятся вне репозитория. Нет другой CRM или второй
системы статусов; кабинет, процесс и генератор используют одну карточку и UUID.

Редактирование данных или повторная сборка отменяют старое утверждение и черновик.
Изменённое VERIFIED-значение без нового свидетельства проверки понижается до
SOURCED и исключается из демо до повторной проверки.
Файлы/проверки и принадлежность сборки повторно проверяются при просмотре,
утверждении и подготовке письма. Оптимистическая версия защищает от параллельного
перезаписывания. Устаревшее задание становится SUPERSEDED. При перезапуске
незавершённая локальная задача возвращается в очередь; блокировка запрещает два
DIRECTOR на одной базе. Остановка очереди не отменяет сборку в работе.

SQLite здесь — исполняемая база первого локального DRY_RUN, без платных сервисов.
Это не утверждение, что подготовленная ранее PostgreSQL/Supabase/Sheets-интеграция
уже работает. Перед внешней отправкой, многопользовательской эксплуатацией и
финансовыми действиями нужна отдельная миграция в согласованную транзакционную
базу, роли, TLS/MFA, резервирование и проверка восстановления. В текущем кабинете
один локальный владелец; Basic Auth подходит только для loopback, не для Интернета.

## Что действительно проверено

30 Python-тестов: предыдущие 24 плюс полный HTTP-цикл, сохранение состояния,
аннулирование согласования, CSRF/401, остановка очереди, конфликт версий и
устаревшая задача, восстановление прерванной сборки и запрет второго DIRECTOR.
`tests/office_ui_check.py` + `office_ui_check.cjs` исполнили
реальные обработчики кнопок через jsdom 26.1.0 против работающего API и записали
тестовую карточку до DRAFT_READY/NOT_SENT. Это DOM/API-проверка, не визуальная
проверка настоящим браузером. Здесь браузерное управление/приватное перенаправление
не предоставлено, поэтому не заявляется проверка пикселей или открытый кабинет
на устройстве пользователя. `node --check office/web/app.js` проверяет синтаксис.
Для DOM-прогона нужен Node и jsdom; они не нужны для обычного запуска кабинета.

Проверочный прогон сохранил 26 HTML-страниц на hy/ru/en, прошёл проверки генератора
и создал персональный черновик с обоими тарифами. Отправленный клиенту email:
**0**. Публичных демо: **0**. Полная стоимость неизвестна; стандартная сборка и
черновик из утверждённого шаблона не вызывают модели/API.

## Осталось подключить

1. **Доступ с телефона:** закрытый сервер с Python, постоянной базой/диском, HTTPS
   и входом только владельца либо запуск кабинета на вашем Windows. Адрес 127.0.0.1
   из удалённой рабочей среды не является ссылкой для вашего устройства. Нужен
   выбор места исполнения; production ELIT DENT и его DNS для этого не нужны.
2. **Настоящее исследование:** Work заполняет конфигурацию и источники; автоматическое
   сетевое исследование и импорт вложений ещё не включены. Фотографии тестового
   примера не переносятся на настоящую клинику. Реальные материалы должны быть
   добавлены в частное хранилище с проверенными правами.
3. **Клиентский доступ:** отдельная закрытая ссылка на демо. В черновике стоит явно
   отмеченный заполнитель, а не ссылка на кабинет владельца. Перед клиентской
   отправкой нужны проверка доступа, адресата и утверждение точного письма.
4. **Почта/договор/оплата:** адаптеры не подключены. Поле delivery всегда NOT_SENT;
   маршрута отправки и кнопки отправки нет. Решение владельца по демо не является
   DEMO_APPROVED клиента и не подтверждает договор или оплату.

Рабочая ветка — `factory/first-working-cycle`, поверх незалитого PR №1.
Автоматическое размещение Vercel для этой ветки выключено. `main`, production,
DNS, исходные клинические данные и проверенный генератор не изменены. Документ —
только короткая инструкция к уже выполняемому коду, а не замена реализации.
